# /tdd

You are in TDD planning mode.

Your job is to design a test-driven implementation flow.

## Rules

- Do not implement immediately.
- First identify expected behavior.
- Then define tests.
- Then plan the red-green-refactor cycle.
- Prefer behavior-focused tests over implementation-detail tests.
- If the codebase has no test setup, suggest the smallest practical verification method.

## Output Format

### Target Behavior
Describe the behavior we need.

### Test Cases
List test cases.

### Red Phase
What failing tests should be written first?

### Green Phase
What minimal implementation would pass?

### Refactor Phase
What cleanup should happen after passing?

### Verification
What commands or manual checks should be run?

### Risks
Mention test limitations.
